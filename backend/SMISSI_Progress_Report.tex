\section{Project Overview}

SMISSI is a production-grade school management platform for Ugandan secondary
schools (target: 5\,000 students). The backend is a \textbf{NestJS monolith}
backed by \textbf{PostgreSQL} with 35+ role-based frontend portals consuming
a single REST API.

\subsection*{Technical Stack}

\begin{tabular}{@{}ll@{}}
  \toprule
  Layer & Technology \\
  \midrule
  Runtime & Node.js 22 / TypeScript 5.7 \\
  Framework & NestJS 11 \\
  ORM & TypeORM 0.3 \\
  Database & PostgreSQL 16 \\
  Queue / Jobs & BullMQ 5 + Redis 5 \\
  Auth & Passport JWT \\
  Real-time & Socket.io 4 (\code{/notifications} namespace) \\
  File storage & Cloudflare R2 via AWS SDK v3 \\
  SMS & Africa's Talking \\
  Email & Resend \\
  PDF & Puppeteer (headless Chromium) \\
  Payments & Pesapal (MTN / Airtel Mobile Money) \\
  Testing & Jest 30 + Supertest 7 \\
  \bottomrule
\end{tabular}

\section{What Has Been Built}

\subsection{Phase 1 --- Database Performance}

Added \textbf{28 indexes} across the most query-heavy tables via
migration \code{003-add-indexes.ts}, all using \code{CREATE INDEX CONCURRENTLY}
so they are safe to run on a live database without table locks.

Critical indexes added:

\begin{itemize}[leftmargin=1.5em, itemsep=0pt]
  \item \code{student\_attendance(school\_id, date DESC)} --- attendance queries (1M+ rows/year)
  \item \code{invoices(student\_id, status)} --- fee defaulter lookups
  \item \code{notifications(recipient\_id, is\_read, created\_at DESC)} --- inbox queries
  \item \code{activity\_logs(school\_id, created\_at DESC)} --- audit trail pagination
  \item \code{messages(to\_user\_id, status, created\_at DESC)} --- messaging inbox
\end{itemize}

TypeORM connection pool configured: \code{max=20, min=2, idleTimeoutMillis=30000}.

The N+1 query in \code{collectionSummary()} was replaced with a single SQL
aggregate using \code{createQueryBuilder(...).groupBy('inv.class\_id')}.

\subsection{Phase 2 --- Redis Caching Layer}

\begin{itemize}[leftmargin=1.5em, itemsep=0pt]
  \item \code{CacheModule.registerAsync()} wired globally in \code{app.module.ts}
    using \code{cache-manager-redis-yet}
  \item Custom \code{AppCacheService} with a \code{getOrSet<T>(key, factory, ttlMs)}
    pattern and \code{delByPattern()} for Redis SCAN+DEL
  \item Cache keys follow the convention \code{domain:role:schoolId:term}
  \item Default TTL: 5 minutes; fee structures cached for 60 minutes
\end{itemize}

\subsection{Phase 3 --- Background Job Queue (BullMQ)}

Five named queues registered globally via \code{QueuesModule}:

\begin{center}
\begin{tabular}{@{}ll@{}}
  \toprule
  Queue & Purpose \\
  \midrule
  \code{payroll} & Payslip generation (transactional, per-run) \\
  \code{pdf} & Puppeteer render then upload to R2 \\
  \code{sms} & Africa's Talking dispatch \\
  \code{email} & Resend dispatch \\
  \code{archival} & Purge activity logs older than 90 days \\
  \bottomrule
\end{tabular}
\end{center}

Each processor uses exponential backoff with 3 retry attempts.
The payroll processor wraps all payslip inserts in a \code{QueryRunner}
transaction --- any single failure rolls back the entire run.

\subsection{Phase 4 --- Six New Feature Modules}

All six modules are fully implemented with entities, service layer,
and role-guarded HTTP controllers.

\subsubsection*{4.1 Payroll}

\begin{itemize}[leftmargin=1.5em, itemsep=0pt]
  \item Entities: \code{PayrollRun}, \code{Payslip}, \code{SalaryComponent}, \code{PayeBracket}
  \item Uganda FY2024/25 PAYE brackets stored in the database (seeded by migration,
    not hardcoded): 0\% up to UGX 235\,000; 10\%; 20\%; 30\% up to UGX 10M;
    40\% above UGX 10M
  \item NSSF: 5\% employee + 10\% employer of gross salary, computed per payslip
  \item \code{POST /payroll/runs} enqueues a BullMQ job and returns
    \code{202 Accepted} immediately --- payslip calculation is fully async
  \item \code{approveRun()} validates DRAFT status before promoting to APPROVED
\end{itemize}

\subsubsection*{4.2 Facilities}

Asset registry (furniture, equipment, vehicles, labs), facility booking with
approval workflow, and maintenance request tracking with priority levels
(LOW / MEDIUM / HIGH / CRITICAL) and status lifecycle.

\subsubsection*{4.3 Uniform}

Per-size stock tracking (\code{UniformStock}). Allocations use a raw SQL atomic
decrement:

\begin{lstlisting}
UPDATE uniform_stock
SET quantity_in_stock = quantity_in_stock - $1
WHERE id = $2 AND school_id = $3 AND quantity_in_stock >= $1
\end{lstlisting}

Checking \code{rowsAffected === 0} throws a \code{ConflictException},
preventing over-allocation under concurrent requests without application-level
locking.

\subsubsection*{4.4 Store}

Inventory items with a stock movement ledger (IN / OUT / ADJUSTMENT) and a
full requisition lifecycle: PENDING $\to$ APPROVED $\to$ FULFILLED.
\code{approveRequisition()} runs inside a \code{QueryRunner} transaction,
decrements each line item atomically, and records partial fulfilment quantities.

\subsubsection*{4.5 SEN (Special Educational Needs)}

Student SEN records with category classification (learning disability, physical,
visual, hearing, speech, behavioural), observation notes (academic impact,
behaviour, recommendations), and accommodation plans with review dates.
Endpoints restricted to teacher-level and above roles only.

\subsubsection*{4.6 Gate}

Student gate passes with a 6-digit random pass code. Role separation enforced:
\code{GATE\_GUARD} can log exits and returns but cannot approve passes;
\code{HEAD\_OF\_BOARDING} and \code{HEAD\_TEACHER} can approve. Visitor
registration with entry/exit timestamps and badge tracking. Socket.io events
are emitted on pass approval and student exit.

\subsubsection*{Migration 004 --- 19 New Tables}

All tables created in a single migration with inline indexes, including:

\begin{itemize}[leftmargin=1.5em, itemsep=0pt]
  \item Partial unique index on gate pass codes:
    \code{WHERE status IN ('APPROVED', 'USED')} --- prevents duplicate
    active codes without blocking historical records
  \item Composite index on payslips for staff history queries
  \item Composite index on SEN records for student-scoped lookups
\end{itemize}

\subsection{Phase 5 --- Real-time Notifications (Socket.io)}

\code{NotificationGateway} on namespace \code{/notifications}:

\begin{itemize}[leftmargin=1.5em, itemsep=0pt]
  \item Clients join rooms \code{school:\{schoolId\}} and \code{user:\{userId\}} on connect
  \item \code{emitToSchool()} and \code{emitToUser()} helpers used throughout services
  \item Events currently wired: \code{boarding:missing-students},
    \code{security:new-incident}, \code{gate:pass-approved}, \code{gate:student-exit}
  \item \code{GatewaysModule} is \code{@Global()} --- injectable anywhere without
    re-importing
\end{itemize}

\code{main.ts} uses \code{IoAdapter} from \code{@nestjs/platform-socket.io}.

\subsection{Phase 6 --- External Integrations}

\begin{itemize}[leftmargin=1.5em, itemsep=2pt]
  \item \textbf{Cloudflare R2} --- \code{StorageService.upload()},
    \code{getPresignedUrl()}, \code{delete()} via \code{@aws-sdk/client-s3}
    pointed at \code{https://\{accountId\}.r2.cloudflarestorage.com}

  \item \textbf{Africa's Talking SMS} --- dispatched through the \code{sms}
    BullMQ queue; never synchronous; retried on failure with exponential backoff

  \item \textbf{Resend Email} --- dispatched through the \code{email} BullMQ queue;
    \code{sendText()} convenience wrapper converts plain text to minimal HTML

  \item \textbf{Puppeteer PDF} --- lazy dynamic import to avoid cold-start cost;
    \code{renderHtml(html) -> Buffer}; PDF uploaded to R2 and URL written back
    to the payslip row by the processor

  \item \textbf{Pesapal} --- OAuth2 token cached for 4 minutes (token TTL is 5 min);
    \code{initiatePayment()} returns a redirect URL; \code{handleIpn()} maps
    the mobile network to the correct \code{PaymentMethod} enum value;
    the IPN webhook endpoint is decorated with \code{@Public()} to bypass
    JWT auth (Pesapal is the caller, not an authenticated user)
\end{itemize}

\subsubsection*{PDF Templates}

Two HTML templates implemented as typed TypeScript functions (no templating
engine dependency):

\begin{itemize}[leftmargin=1.5em, itemsep=0pt]
  \item \code{payslipTemplate(data)} --- UGX-formatted payslip with PAYE,
    NSSF, optional SACCO row, net pay box
  \item \code{invoiceTemplate(data)} --- fee invoice with coloured status badge,
    line items table, balance due
\end{itemize}

\subsection{Admin Module --- Stubs Replaced}

11 stub methods that returned in-memory seed arrays were replaced with real
TypeORM queries. Three new entities added: \code{AcademicTerm},
\code{SupportTicket}, \code{IntegrationConfig} (migration \code{005-admin-entities.ts}).

\section{Testing Strategy}

\subsection{Unit Tests}

Each service is tested in isolation with mocked TypeORM repositories,
mocked BullMQ queues, and a mocked \code{DataSource}. No external connections
required. Key coverage areas:

\begin{itemize}[leftmargin=1.5em, itemsep=2pt]
  \item \textbf{Payroll PAYE} --- 9 cases covering all Uganda FY2024/25 tax
    brackets including zero-tax threshold (UGX 235\,000) and top 40\% band
  \item \textbf{Finance collection summary} --- field name assertions on
    \code{termTarget} and \code{totalCollected}
  \item \textbf{Gate pass code uniqueness} --- 100 sequential calls produce
    over 50 distinct codes (birthday-problem sanity check)
  \item \textbf{Store manual adjustment} --- negative resulting stock throws
    \code{ConflictException}
  \item \textbf{Uniform atomic decrement} --- \code{dataSource.query} mock
    returns \code{rowsAffected = 0} to simulate concurrent over-allocation
  \item \textbf{PDF templates} --- 22 pure function tests with no browser or
    mocks; asserts UGX number formatting, conditional SACCO row, status badge
    colour selection
\end{itemize}

\subsection{Integration Tests}

Each suite spins up a real NestJS \code{TestingModule} with the actual
\textbf{controller, guards, pipes, and interceptors} wired. Services are mocked.
JWT tokens are signed with the dev fallback secret and verified by the real
\code{JwtStrategy}, so the full authentication pipeline executes.

Each suite verifies:

\begin{itemize}[leftmargin=1.5em, itemsep=2pt]
  \item \textbf{401} on missing \code{Authorization} header
  \item \textbf{403} on wrong role (e.g.\ \code{TEACHER} hitting payroll endpoints)
  \item \textbf{400} on \code{ValidationPipe} rejection (missing required fields)
  \item Correct HTTP status per endpoint (\code{202 Accepted} for job enqueue,
    \code{204 No Content} for logout)
  \item \code{TransformInterceptor} envelope shape: \code{\{data, statusCode, timestamp\}}
  \item Service called with correct school-scoped and user-scoped arguments
  \item IPN webhook (\code{POST /finance/ipn}) accessible without a JWT token
  \item Pesapal payment amount calculated as \code{invoice.amount - paidAmount}
\end{itemize}

\subsection{Bugs Found During Testing}

\begin{tabular}{@{}p{4.8cm} p{9.2cm}@{}}
  \toprule
  Bug & Fix \\
  \midrule
  IPN orderId regex stopped at the first hyphen, extracting only the first
  segment of a UUID invoice ID &
  Changed the regex to a greedy match up to the trailing numeric
  timestamp: \verb|^INV-(.+)-\d+$| \\
  \addlinespace[6pt]
  \code{POST /finance/ipn} returned 401 because the class-level
  \code{@UseGuards} blocked the Pesapal webhook caller &
  Added \code{@Public()} decorator; updated \code{JwtAuthGuard} to
  check \code{Reflector} and skip JWT verification on marked handlers \\
  \bottomrule
\end{tabular}

\section{Architecture Decisions}

\begin{tabular}{@{}p{4cm} p{10cm}@{}}
  \toprule
  Decision & Rationale \\
  \midrule
  \code{QUEUE} constants extracted to a separate file &
  \code{@Processor(QUEUE.X)} runs at class decoration time. Importing from
  \code{queues.module.ts} caused a circular reference where \code{QUEUE}
  was \code{undefined} at decoration time. \\
  \addlinespace[6pt]
  Atomic stock decrement via raw SQL &
  ORM-level read-modify-write has a TOCTOU race under concurrent requests.
  \code{UPDATE ... WHERE quantity >= \$1} is atomic at the database level. \\
  \addlinespace[6pt]
  PDF templates as plain TypeScript functions &
  No Handlebars or Nunjucks dependency. Templates are fully type-checked,
  testable without a browser, and trivially tree-shakeable. \\
  \addlinespace[6pt]
  Payroll processor inside a \code{QueryRunner} &
  A payroll run may produce hundreds of payslips. Any single insert failure
  must roll back the entire batch; partial payrolls are worse than no payroll. \\
  \addlinespace[6pt]
  Infrastructure modules marked \code{@Global()} &
  \code{GatewaysModule}, \code{StorageModule}, \code{SmsModule},
  \code{EmailModule}, \code{PdfModule} are global so any feature module
  injects them without re-importing. \\
  \addlinespace[6pt]
  Pesapal token cached for 4 minutes &
  Pesapal OAuth2 tokens expire after 5 minutes. The 1-minute buffer prevents
  using an expired token on a payment initiated at the last second. \\
  \bottomrule
\end{tabular}
